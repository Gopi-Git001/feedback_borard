## Rules for using this file
- Pin **major.minor** in code and CI, with the exact verified patch as a lower bound. Use a lock file (`uv.lock` / `package-lock.json`) so installs are reproducible.
- Python packages: use compatible-release pins (`~=`). For 0.x packages (FastAPI, Uvicorn) the minor version is treated as breaking, so `~=0.162.0` means "0.162.x only".
- No beta / RC / dev / canary / EOL versions anywhere. Verified: every version below is a plain stable release (no `rc`, `beta`, `dev`, `canary`, `pre` suffix) and none is yanked or deprecated on its registry.
- Changing any pin needs an ADR (supersede ADR-001) and Orchestrator go-ahead.

## Notes and exceptions (honest flags)
1. **argon2-cffi** last release is 2025-06-03, older than the 12-month freshness rule in tech-research. It is not abandoned: the repository had a commit on 2026-10-01 (https://github.com/hynek/argon2-cffi), there is no deprecation notice, and it is the Argon2 binding that the pwdlib package (0.3.1, 2026-08-12) wraps via its `argon2` extra (PyPI metadata). bcrypt 5.0.0 (2025-09-25) is also older than 12 months, so neither option passes the rule; argon2 was chosen on merit (ADR-002). Accepted exception, flagged for the Orchestrator.
2. **email-validator** 2.3.0 is from 2025-08-26 (older than 12 months by 2026-08-26). Repository active (commit 2026-10-15). Accepted exception; it is a transitive requirement of Pydantic `EmailStr`.
3. **Test HTTP client: httpx2 replaces httpx (attempt 12; ARCHITECT DECISION, not approved by Gopi).** Verified 2026-10-27 (about 10:15 PM CDT). **httpx2:** PyPI `httpx2` 2.16.0, released 2026-10-21, `Development Status :: 5 - Production/Stable`, not yanked, Python >=3.11 (3.14 is fine), requires `anyio`, `httpcore2` (exactly 2.16.0), `idna` and `truststore`; 21 releases in the 2.x line since 2.0.0 on 2026-05-12 (about one a week). Its README (https://github.com/pydantic/httpx2) says it is a continuation of HTTPX: "With HTTPX itself seeing limited activity recently, Pydantic is picking up stewardship under the HTTPX2 name". It is not published by the original HTTPX project, so "successor" here means Pydantic's continuation, not a rename by the original maintainers. **Starlette 1.10.0** (2026-10-24, the version locked in `backend/uv.lock`): https://starlette.dev/testclient/ says "The `TestClient` is built on `httpx2`. Plain `httpx` is still supported, but deprecated - install `httpx2` (included in `starlette[full]`) instead." Release notes (https://starlette.dev/release-notes/): 1.2.0 (2026-05-28) "Support httpx2 in the test client"; 1.2.1 uses httpx2 for type checking; 1.3.0 (2026-06-11) "Add `httpx2` to the `full` extra". The `full` extra of 1.10.0 lists both `httpx2>=2.0.0` and `httpx>=0.27.0,<0.29.0`; no release note says httpx support is removed. **FastAPI 0.162.0** (2026-10-23): its `standard`, `standard-no-fastapi-cloud-cli` and `all` extras list both `httpx>=0.23.0,<1.0.0` and `httpx2>=2.0.0`; the FastAPI testing page (https://fastapi.tiangolo.com/tutorial/testing/) still says to `uv add httpx`, so it lags Starlette. **httpx:** 0.28.1 (2024-12-06) is still the latest stable; only `1.0.dev1` to `1.0.dev6` pre-releases follow it (`1.0.dev6` 2026-08-31), which are forbidden. **Observed:** with httpx 0.28.1, importing `fastapi.testclient` emits `StarletteDeprecationWarning: Using httpx with starlette.testclient is deprecated; install httpx2 instead` (backend-bot's TASK-004 PR #22 finding, reproduced by architect-bot from the lock file on main `364d9b9`). Replacing httpx with httpx2 2.16.0 in that environment removed the warning; the tests that need no database passed in both cases (24 passed; the other 5 failed in this sandbox for lack of PostgreSQL or a `.env`, the same ones with both clients, and one startup test was flaky here, so the count varied between 24 and 25). backend-bot's own run is the authority: 29 tests with a database. **Decision:** pin `httpx2` `~=2.16.0` in the backend dev dependency group (tests only) and drop `httpx ~=0.28.1`. Treat the httpx2 minor as breaking (it releases about weekly and `httpcore2` is pinned to the same version). backend-bot makes the change in a follow-up (`pyproject.toml`, `uv.lock`, and `DEV_PINS` in `backend/tests/test_project_pins.py`, which currently asserts `httpx ~=0.28.1`) and re-runs all tests. Until then httpx 0.28.1 with the deprecation warning is tolerated: nothing fails. **Re-check condition (dated 2026-11-10):** if any backend test fails with httpx2 on the lock, or a newer httpx2 minor or a Starlette release changes the TestClient requirement, keep httpx 0.28.1 and record the reason here. httpx is then no longer a freshness exception.
4. **TypeScript 6.0.3, not 7.0.2.** TypeScript 7.0.2 (2026-07-08) is the current `latest` on npm and is stable. It is **not pinned** because typescript-eslint 8.72.1 (the current release) declares peer `typescript >=4.8.4 <6.1.0`, so TS 7 would break the lint step required by the frontend checks in CI. 6.0.3 is the last 6.x release and is not deprecated. Revisit when typescript-eslint supports TS 7 (new ADR). **TypeScript 6.0.3 is confirmed** (Orchestrator message 2026-10-27, relayed from the human).
5. **React Router**: the `latest` tag of `react-router` is 8.5.1 (npm registry, published 2026-10-27 21:39 UTC; re-checked in attempt 12, and reactrouter.com shows "latest (8.5.1)" in its version selector). `react-router-dom` is only published as the 7.x line (latest 7.18.5, dist-tag `latest`) and is **not installed**.
